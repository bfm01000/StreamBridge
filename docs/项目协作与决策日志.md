- **Linux 发行版和版本**：Ubuntu 24.04, x86_64, kernel 6.17.0-19-generic
- **编译器版本**：gcc/g++ 13.3.0 (Ubuntu 13.3.0-6ubuntu2~24.04.1)，支持 C++17
- **CMake 或 Make 选择**：CMake 3.28.3 + GNU Make 4.3
- **FFmpeg 安装方式**：源码构建，版本 N-123159，`--enable-debug`；库版本：libavcodec 62.24.101, libavformat 62.10.101, libavutil 60.25.100, libavdevice 62.2.100, libswscale 9.4.100, libswresample 6.2.100

- **SRS 运行方式**：当前未安装 SRS；建议本机源码编译或 Docker 运行；待用户确认
- **动态库搜索路径**：`/usr/local/lib`（FFmpeg 自编译默认路径）
- **可执行文件输出路径**：`linux/build/`（待 CMake 配置时确定）
- **构建命令**：待 CMake 工程创建后确定，初步为 `mkdir -p linux/build && cd linux/build && cmake .. && make`
- **运行验证命令**：`ffplay` 和 `ffprobe` 均在 `/usr/local/bin/` 可用

### 2026-08-11 Android AI MediaCodec Freeze Bugfix

- 问题现象：切到 MediaCodec zero-copy 后，画面显示前几帧后卡住不动；日志中硬解已成功配置并持续输出 frame，但 `sync=Drop`，`video_packet_queue` 接近满。

### 2026-08-14 Linux AI Camera+ALSA AV Sync Fix & Sync Test

- 问题现象：camera+ALSA 推流音画不同步（本地文件源推流同步正常）。
- 根因（三层叠加）：
  1. V4L2/ALSA 采集 PTS 用 `frame_idx × 名义时长` 合成，两路各自从 0 起算，启动时刻差变成恒定偏移，丢帧/XRUN 后漂移；
  2. `FFmpegAudioEncoder` 输出 PTS 用内部计数器（与输入帧 PTS 完全脱钩），音频时间轴被归零，与视频绝对时钟错位；且累积器每 16 chunk 重启时全局帧计数重复叠加，PTS 周期性跳变 ~350ms；
  3. mux 无跨流起始对齐；对齐器初版「对齐前立即丢弃单路包」导致两路首包几乎永远不同时在队（33ms/21ms 到达网格），对齐被拖到超时。
- 修复内容：
  1. 采集 PTS 统一 CLOCK_MONOTONIC（V4L2 优先驱动 `buf.timestamp`，无则出队时刻；ALSA 用 read 完成时刻）；
  2. 音频编码 PTS = 累积器首采样采集时刻 + 本轮帧偏移×帧长（帧偏移每轮归零）；
  3. 新增公共纯逻辑类 `AvStartAligner`：对齐前只等待不丢弃，双路首包齐备后 base=max(两路首包)，低于 base 的包丢弃，其余平移；3s 超时保护；
  4. 修复 mux 旁路 pop 绕过对齐器的问题（对齐前不消费）。
- 新增测试：
  - `test_av_start_aligner`（纯逻辑单元测试，无设备依赖，22 断言全过）；
  - `av_sync_capture_test`（真实 camera+ALSA 走生产链路录制 10s 到 `source/av_sync_test.flv` 并离线分析；设备缺失时 SKIP）。
- 验证结果：10s 录制：start skew +20ms、drift +9ms、v/a max gap 45/78ms、PASS；`ctest` 2/2 通过。
- 修改文件：`linux/platform/capture/{v4l2_video_capture,alsa_audio_capture}.cpp`、`common/src/ffmpeg/ffmpeg_audio_encoder.{h,cpp}`、`common/src/session_impl.cpp`、`common/include/streambridge/av_start_aligner.h(新增)`、`common/tests/av_start_aligner_test.cpp(新增)`、`linux/tests/av_sync_capture_test.cpp(新增)`、`linux/tests/CMakeLists.txt`、`docs/测试指南.md`、`docs/项目协作与决策日志.md`、`.gitignore`。

  - Stop order remains request stop -> abort queues -> interrupt/close socket -> join threads -> close decoders/resources.
